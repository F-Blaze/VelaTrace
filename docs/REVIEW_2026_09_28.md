# Routing feedback and timing review — 2026-09-28

Base: merged PR #11 (`dc511ce`). This review used two parallel sub-agents and root
integration testing. No user project, its text, or its detailed DRC reports are
included in the repository. Local project diagnostics used disposable copies only.

## Findings and changes

- Approve already called the copper writer, not Freerouting. Actual Qt-button
  regressions now prove preview generation and approval take separate paths.
- A copied project produced blocking clearance errors against copper text. The
  old preview message still invited approval even when its button was disabled.
  The UI now explicitly names blocking DRC types and distinguishes them from
  carried warnings; it reports applied copper or an unconfirmed result persistently.
- At a requested 650px height, the old window expanded to 730px. A scrollable routing
  page keeps approval reachable even with long validation summaries.
- Saved User.9 graphics exposed a second failure: KiCad replaced one existing line
  when a new preview had identical geometry. The board-change guard correctly
  refused approval. A new preflight collision check refuses before writing, leaving
  unowned graphics intact. No arbitrary layer-wide cleanup is implemented.
- Copper is read back after commit by UUID and geometry. An acknowledgment without
  matching real tracks/vias can no longer be reported as a successful application.
- The UI shows elapsed time, current stage, and separate routing/DRC/preview/apply
  durations. Routing avoids one redundant startup-directory offline probe while
  retaining the JAR hash, Java version and actual-directory offline policy checks.

## Performance evidence and limits

On a synthetic fixture, one removed probe cost about 0.7 seconds. Total routing
measured 11.5 seconds before and 8.8 seconds after, but startup/cache variation
contributes to that difference; it is not a promised speedup. A local project
copy took about 7–8 seconds routing and 17–23 seconds in candidate validation.
Required DRC, backups, routing effort and external-process network denial remain.

The actual Qt Approve button on the synthetic fixture created one real F.Cu track,
removed the User.9 preview, and completed in 0.3 seconds without rerouting. One Undo
reverted copper and restored the preview. Saved board bytes stayed unchanged.
Project-specific DRC and saved-preview problems are distinct from the routing
capability itself. Copper-zone filling remains a separate, unsupported operation.

After correcting only the disposable project's copper-text placement and removing
its saved User.9 preview graphics, real routing produced 51 tracks on F.Cu/B.Cu
with zero blocking DRC issues and zero unconnected items. The actual Qt approval
button applied and verified all 51 tracks in 0.8 seconds. One Undo restored the
preview and removed all copper; guarded cleanup succeeded. The original project
and saved copy bytes remained unchanged. That run measured 5.3 seconds routing and
14.5 seconds validation; timings vary between runs.

Final regression suite: **173 tests and 114 subtests passed, zero skips**, including
real Freerouting/Java and KiCad CLI. Ruff passed. The new collision regressions
cover reversed endpoints, owned replacements, distinct layers, duplicate incoming
segments, and refusal before any commit. Existing backup, rollback and uncertain
write checks remain. This is development evidence, not a signed release.
