# Preview approval and repository review — 2026-09-27

Base: `49e7278` on main. This is development review evidence, not a signed release
or a claim that all defects have been eliminated.

## User-visible correction

After Confirm constraints produces the User.9 preview, approve without saving.
The candidate now uses the actual live PCB snapshot. Approval compares that
validated snapshot with the current live board, excluding only exact, verified
temporary items owned by this plugin session. Preview removal and copper creation
remain one backed-up IPC commit. Edits after validation require revalidation;
they do not require saving temporary graphics. Initial saved project/rules and a
fresh manual DSN export are still required.

The original simple preview could not reproduce the user's remembered save error
on the latest main. The change removes the disk-versus-live save gate and adds
direct coverage for the requested unsaved approval behavior.

## Other confirmed fixes

- Redundancy matching preserves case-sensitive SI values, so `1mOhm` and `1MOhm`
  cannot become duplicate candidates through case folding.
- XML parsing rejects DTD declarations even in UTF-16 netlists.
- Freerouting startup no longer deletes every directory matching `route-*` or
  `startup-*`, which could belong to another active session or the user.
- DRC issues missing reliable identities cannot receive a pre-existing-warning
  exemption merely because their missing fields compare equal.
- Accepting Setup changes retires the old audit/provider/key even when router
  verification fails. Cleanup failures retain the safety handle and owned graphics.
- Approval rechecks live geometry after beginning the transaction, before creating
  copper, to catch edits made during backup or journal creation. Live backup data
  is flushed to disk before mutation.

## Limits and release gates

One two-pad route does not certify every geometry, KiCad version or OS. Saved
project rules are validated; unsaved Board Setup changes are not readable by this
adapter. Do not edit during an operation. Existing copper, header keepouts,
hierarchical schematic context and unsupported SES geometry still refuse.

Groq tokenizer parity remains unverified; do not mark the tokenizer verified merely
to enable classification. Broader provider acceptance, independent PR approval,
a trusted second code owner and a trusted signed release remain required. No tag
or release was created. Historical build and review notes retain their original
dates and narrower evidence.
